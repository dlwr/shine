# フロントエンド・デザイン刷新：Editorial Brutalist Cinema

- 日付: 2026-05-20
- 対象: `apps/front`（React Router v7 / Cloudflare Workers SSR / Tailwind v4）
- ステータス: 設計確定（実装計画はこの後 writing-plans で作成）

## 1. 目的とコンセプト

SHINE の公開ページのデザインを「ワクワクする・先鋭的」に全面刷新する。現状は shadcn/ui のデフォルトテーマ（グレー基調・無難）。

採用する方向性は **Editorial Brutalist Cinema**。3つのテイストの融合：

- **A. ネオブルータリズム**（骨格）— 極太の枠・ハードなオフセット影・ソリッドな原色。グラデーションは使わない。
- **B. シネマティック・ノワール**（ステージ）— 暗がりの中でポスターだけがほのかに発光する映画館的演出。
- **D. スイス／エディトリアル**（規律）— 硬質なグリッド、巨大な年号、等幅フォントのメタ情報、新聞的マストヘッド、一点のアクセント。

> 不採用: C（キネティック・グラデーション）。グラデは全面的に使わない。

## 2. スコープ

### 含む

- 公開3ページのレイアウト／UX を作り直す: `home`(`/`), `movies.$id`(`/movies/:id`), `search`(`/search`)。
- デザイントークン（テーマ）の再定義（ライト／ダーク両対応）。
- 公開ページ用のデザインプリミティブ層の新設。
- ダークモードの配線（OS追従＋手動トグル＋永続化、フラッシュ防止）。
- フォント読込戦略の実装。
- 上記に伴う既存テスト（後述）の書き直し。

### 含まない

- 管理画面（`admin.*` ルート）— shadcn/ui のまま据え置き。テーマトークン変更の影響は受けるが、レイアウト改修はしない。
- API・スクレイパー・DB スキーマの変更。
- 機能追加（配信サービス・記事リンク・受賞表示などの機能仕様は現状維持。見せ方のみ変更）。

### 補足

- 実構造は `apps/front/`（CLAUDE.md は古い `front/` 前提の記述が残るが、本 spec のパスはすべて `apps/front/` を正とする）。CLAUDE.md 本体の修正は本タスクのスコープ外（必要なら別タスク）。

## 3. デザイントークン

CSS 変数で定義し、`.dark` クラスで上書きする（既存 `app.css` の構造を踏襲）。色は WCAG AA を満たすよう調整する（§8）。

### ライト（昼 / 紙・ボーン）

| トークン      | 値                                                     | 用途                                       |
| ------------- | ------------------------------------------------------ | ------------------------------------------ |
| `--bg`        | `#ECE8DF`                                              | 背景（紙）                                 |
| `--surface`   | `#FFFFFF`                                              | カード面                                   |
| `--ink`       | `#15140F`                                              | 主要テキスト・枠                           |
| `--ink-muted` | AA を満たす濃さに調整（`#777` は不可、`#595650` 目安） | メタ情報                                   |
| `--accent`    | `#FF3B30`                                              | アクセント（受賞・重要情報・オフセット影） |
| `--poster-bg` | `linear-gradient(160deg,#2a2330,#0e0d12)`              | 暗いポスター窓                             |

### ダーク（夜 / チャコール）

| トークン        | 値                                                                | 用途               |
| --------------- | ----------------------------------------------------------------- | ------------------ |
| `--bg`          | `#18181D`                                                         | 背景（チャコール） |
| `--surface`     | `#202027`                                                         | カード面           |
| `--ink`         | `#EDEAE3`                                                         | 主要テキスト・枠   |
| `--ink-muted`   | AA を満たす明るさに調整（`#8a8a86` は不可、`#A8A8A2` 目安）       | メタ情報           |
| `--accent`      | `#FF3B30`                                                         | アクセント         |
| `--poster-glow` | `radial-gradient(circle, rgba(255,233,180,.28), transparent 70%)` | ポスターの発光     |

共通の造形トークン:

- 枠: `3px solid var(--ink)`（主要）/ `2px`（副次）
- オフセット影（ブルータリズム）: `box-shadow: 6px 6px 0 var(--accent)`（ヒーロー）/ `5px 5px 0`（カード）
- 角丸: なし（`border-radius: 0`）

## 4. タイポグラフィ

3系統で構成する。

- **表示用グロテスク**（見出し・巨大年号・タイトル）: Space Grotesk もしくは Archivo（最終選定は実装時、可変フォント優先）。極太ウェイト＋強いネガティブ・トラッキングで使う。
- **等幅**（メタ情報・ラベル・ナンバリング）: 等幅フォント（候補 JetBrains Mono / IBM Plex Mono、または system monospace でも可）。
- **本文**: 現行の Inter を継続。

### 読込戦略（FOUT 対策）

- 表示用グロテストと等幅は **self-host**（`apps/front/public/fonts/` に配置）し、`root.tsx` の `links` で `preload`。
- `font-display: optional`（巨大年号での字形シフトを避ける）。本文 Inter は `swap` でも可。
- 既存の Google Fonts からの Inter 読込は self-host に寄せるか維持かを実装時に判断（最低限 preconnect は残す）。

## 5. ページ別レイアウト

### 5.1 ホーム `/`

- **マストヘッド**: 左に極太グラデなしの `SHINE`（ライトは ink、ダークは ink）、右に等幅のタグライン＋日付、下に 2px の太罫。言語切替・検索・テーマトグルもここに収める。
- **3 セレクション**: 日替わりを主役（`flex 1.4`）に大きく、週替わり・月替わりを右に2段積み。
  - 日替わりカード: 上部に反転帯（`DAILY / 日替わり` ＋ `NO.001`）、本体に「光るポスター＋巨大年号（下2桁を赤）＋タイトル＋等幅メタ＋受賞チップ」。枠 3px ＋赤オフセット影。
  - 週/月カード: 縦帯ラベル＋年号＋タイトルのコンパクト版。
- **再抽選**（管理者時のみ表示）等の既存機能は維持。

### 5.2 映画詳細 `/movies/:id`

- 戻りリンク（等幅）。
- **ヒーロー**: ポスター（枠＋赤オフセット影）＋巨大年号（下2桁赤）＋タイトル＋等幅メタ（監督・国・尺）。下に太罫。
- **AWARDS ツリー**: 組織ごとに黒帯ヘッダ（`ACADEMY AWARDS · 1995`）、その下にカテゴリ行をハード罫線で区切る。受賞は赤バッジ `★ WINNER`、ノミネートは枠線バッジ `NOMINEE`。組織→開催回→カテゴリの既存階層を踏襲。
- **WATCH（配信）**: 既存のサービス群。**ブランド色は維持**（U-NEXT 黒 / Prime 青 / Filmarks 紫 / IMDb 等）し、**枠と影だけ**新デザイン言語（`2px solid var(--ink)` ＋ `2px 2px 0 var(--ink)`）に統一する。現状のホバーメニュー実装の中身は流用。
- **LINKS（投稿記事）**: 赤の縦罫＋タイトル行。`+ リンクを追加` も同列。スパム/レート制限など既存仕様は不変。
- ポスターが複数ある場合は `selectBestPoster` で主ポスターを選ぶ既存ロジックを維持。

### 5.3 検索 `/search`

- 見出し `SEARCH`。
- **検索窓**: 極太枠＋赤オフセット影の入力＋黒い `GO`。既存のデバウンス検索を流用。
- **フィルター**: 等幅チップ（ALL / AWARD WINNERS / DECADE ▾ など。現行フィルター項目に合わせる。新規フィルターは追加しない）。
- **結果**: 「年号（下2桁、受賞は赤）＋極小ポスター＋タイトル＋等幅監督名＋受賞★」のエディトリアル行を、行間 2px 罫線で区切るリスト。件数を等幅で表示。

### 5.4 ダーク版

全ページとも**構造は同一**で、トークンの値だけがチャコール側に反転する。ポスターは紙モードでは「暗い窓」、チャコールモードでは「発光」する。

## 7. ダークモードの配線

- **既定**: OS の `prefers-color-scheme` に追従。
- **手動トグル**: `ThemeToggle` で `light`/`dark` を切替、`localStorage`（キー例 `shine-theme`）に永続化。値があれば OS 設定より優先。
- **フラッシュ防止**: `root.tsx` の `<head>` 内に小さなインラインスクリプトを置き、hydration 前に `localStorage`/`matchMedia` を読んで `<html>` に `dark` クラスを付与する。
- `<html lang>` は現状 `en` 固定。locale 連動は本タスクのスコープ外（必要なら別途）。

## 8. アクセシビリティ

- **コントラスト**: 全テキスト・全 UI 要素・全アクセント配色を WCAG AA（本文 4.5:1、大文字 3:1）で検証する。特に `--ink-muted` の等幅メタ情報はライト/ダーク双方で AA を満たす値に調整（現モックの `#777` / `#8a8a86` は不可）。
- **フォーカス可視**: キーボードフォーカスリングをアクセント色で明示。
- **セマンティクス**: マストヘッドの `SHINE` は `h1`、各セクション見出しは適切な heading レベル。受賞バッジは色だけでなくテキスト（WINNER/NOMINEE）でも区別。
- **テーマトグル**: `aria-pressed` 等で状態を伝える。

## 9. モーション（量: しっかり）

- **入場**: セレクションカード・検索結果行のスライドイン／フェード（段階遅延）。
- **巨大年号**: 表示時のカウントアップ演出（詳細・ホームのヒーロー）。
- **ポスター**: ホバーで発光が強まる／わずかに浮く。配信メニューの出現アニメーション。
- **prefers-reduced-motion**: `@media (prefers-reduced-motion: reduce)` で上記アニメーションをすべて無効化（即時表示・カウントアップなし）。これは必須。
- 既存の `tw-animate-css` を活用しつつ、必要なキーフレームを `app.css` に追加。

## 10. テスト方針

- 既存の公開ページテスト（`home.test.tsx` 8、`movies.$id.test.tsx` 10、`search.test.tsx` 11）は DOM 構造前提が変わるため**書き直す**。これをスコープに含める。
- `admin.*` のテストは原則不変（テーマトークン変更で表示が変わる程度。DOM 構造を壊さない）。
- CLAUDE.local.md の TDD 原則に従い、**各ページ／プリミティブごとに「テスト更新 → 実装」**の順で進める。ローダのデータ取得・主要素のレンダリング・受賞/配信/記事リンクの表示・テーマトグルの挙動を検証対象にする。
- `prefers-reduced-motion`・コントラストは自動テストが難しいため、実装時の手動確認チェックリストに含める。

## 11. リスクと留意点

- **巨大年号 × モバイル**: 狭幅では巨大年号・大ヒーロー・オフセット影が破綻しやすい。`>= md` でヒーロー構成、モバイルは年号を縮小し縦積みの別構成にする（モバイルファーストで設計）。既存の MovieCard モバイル折りたたみ挙動は要否を再検討。
- **配信ブランド色 × 新デザイン**: ブランド色は不可変。枠/影のみ統一する方針を厳守（§5.2）。
- **フォント読込**: self-host ＋ preload ＋ `font-display: optional` を守らないと巨大年号で FOUT が目立つ。
- **テスト破壊**: 公開ページテストの書き直しを最初に計画へ組み込む。
- **CLAUDE.md パスずれ**: 実装中の参照は常に `apps/front/`。

- OS追従＋手動トグル＋永続化＋フラッシュ防止が動作する。
- 全配色が WCAG AA を満たす。
